共通語意基座

整個作業採三層式架構：數值層產生事實，Grounding 層把事實轉成 RDF，語意層做 OWL 推理與 SPARQL 查詢。

1 · 數值層fk.py / ik.py / ravens — 關節角、pose、殘差、reward（PyBullet 模擬）
│ Symbol Grounding（ground_task*.py + common.py 序列化 helper）▼
2 · 語意層hw3-ontology.ttl 共用詞彙 + 各任務知識圖（Turtle，結構化節點）
│ Jena OWL Reasoner ▼
3 · 推理層一致性檢查 + 具體化：評估類（PassedFK / SolvedIK / SuccessfulEpisode）與 gate 類全由推理導出
│ TDB2 / Fuseki 載入 ▼
4 · 查詢分析層q1–q4 SPARQL + 練習 1–3：規格摘要、限位審計、軌跡分析、跨機器人互通比較
│ 推理結果驅動動作裁決 ▼
5 · 決策層Semantic Gate（練習 4・加分項目）：ALLOW / REFUSE ＋ 可解釋的推理鏈

結構化三原則

  1. 不用 JSON 字串。Pose 與關節向量是結構化節點：soma:6DPose = pos:Position（x/y/z）＋ hw3:QuaternionOrientation（qx/qy/qz/qw）＋ 參考座標系；關節組態 = hw3:JointConfiguration 聚合 6 個 soma:JointState，每個以 hw3:isStateOfJoint 指回關節個體。
  2. 數值是型別化 literal、單位是 QUDT IRI。一律 "..."^^xsd:double（裸浮點會變 xsd:decimal 觸發 range 檢查錯誤）；qudt:hasUnit unit:M / unit:RAD。
  3. 每個個體帶 hw3:producedBy。獨立程式（你的 UR5、TA 的 UR10）寫進同一個 store 仍可區分與互查。
標準引用 既有本體詞彙（IRI 與官方一致，離線存根） hw3: 自創 課程特有概念 推理導出 只由 OWL reasoner 具體化，程式從不直接寫入
TASK 1

Forward Kinematics — 正向運動學

實作 your_fk()：classic DH 連乘求 EE pose ＋ 幾何 Jacobian。語意層 ground 兩件事：機器人規格（關節個體＋DH 參數）與每筆測資的評估結果。

過程

  1. 實作 fk.py 的 your_fk(DH_params, q, base_pos)；python fk.py 以 easy / medium / hard 測資評分（pose 誤差門檻 0.005、Jacobian 門檻 0.05，各 10%）。
  2. semantic/ground_task1_fk.py 對 3 筆 easy 測資執行 your_fk，與 ground truth 比對得 pose_error / jacobian_error → PASS / FAIL。
  3. Ground 機器人規格：stu:my_ur5 a cora:Robot ＋ 6 個 soma:RevoluteJoint 個體（DH a/d/α、限位、關節序）。
  4. Ground 每筆 FK 評估：輸入關節組態與 EE pose 都是結構化節點 → 輸出 output/task1_fk_graph.ttl。

語意定義

詞彙來源定義
cora:RobotCORA機器人個體（stu:my_ur5、ta:ta_ur10）
soma:RevoluteJointSOMA旋轉關節個體，掛 hw3:jointIndex、hw3:dh_a / dh_d / dh_alpha、上下限位
hw3:hasJointhw3:機器人 → 關節（⊑ dul:hasComponent）
hw3:FKComputationhw3:一次 FK 計算（⊑ hw3:KinematicComputation ⊑ dul:Event）
hw3:hasInputJointConfigurationhw3:ObjectProperty → hw3:JointConfiguration（6 × soma:JointState）
hw3:hasEndEffectorPosehw3:ObjectProperty → soma:6DPose（world frame）
hw3:hasPoseError / hasJacobianError / hasEvaluationStatushw3:與 GT 的 L2 誤差（xsd:double）、"PASS"/"FAIL"（數值層判定）

為下游而 ground：限位 → 練習 1（限位審計）；DH 參數 → 練習 3（臂長證據）；PASS → q4 評估報表。這些欄位是需求，不是建議。

TASK 2

Inverse Kinematics — 逆向運動學（含軌跡 Grounding）

實作 your_ik()：Damped Least Squares 迭代解，靠 your_fk 提供 pose 與 Jacobian。語意層 ground 三件事：求解狀態、結構化關節解、以及 solver 的逐迭代收斂軌跡。

過程

  1. 實作 ik.py 的 your_ik(robot_id, pose, base_pos, ..., trajectory_out=None)；python ik.py 評分（誤差門檻 0.02，40%）。trajectory_out 是統一介面：傳入 list 即記錄每次迭代的 (iteration, q, EE pose, residual)。
  2. semantic/ground_task2_ik.py 對三個共用目標（hw3:target_near / target_mid / target_far）呼叫 your_ik(..., trajectory_out=[])。
  3. 依殘差與工作空間幾何判定狀態：SOLVED / OUT_OF_REACH / NO_CONVERGENCE。
  4. Ground IK 結果 ＋ 軌跡（降採樣至 ≤ 6 個樣本、保頭尾）→ output/task2_ik_graph.ttl。

語意定義

詞彙來源定義
soma:6DPose（⊑ pos:Pose, dul:Region）SOMA共用目標 hw3:target_*：跨圖比較的 join key，座標在 pos:Position 元件節點上
hw3:IKComputationhw3:一次 IK 計算（⊑ dul:Event）
hw3:solvesForTargethw3:IK → 目標 pose（⊑ dul:hasRegion）
hw3:hasIKStatus / hasResidualhw3:求解狀態字串、Cartesian 殘差（公尺）
hw3:hasJointConfigurationhw3:ObjectProperty → 結構化 hw3:JointConfiguration
hw3:SolverTrajectory（⊑ soma:Trajectory）SOMA hw3:solver 在關節空間的收斂路徑
hw3:TrajectorySamplehw3:一個樣本：hasSampleIndex / atSolverIteration / hasSampleResidual ＋ 關節組態 ＋ EE pose（由 your_fk 計算）
dul:directlyPrecedesDUL樣本間的順序鏈

範例（你的圖應長這樣）

stu:ik_target_near a hw3:IKComputation ;
    hw3:producedBy "313551000" ;
    hw3:computedForRobot stu:my_ur5 ;
    hw3:solvesForTarget hw3:target_near ;        # 共用 URI = join key
    hw3:hasIKStatus "SOLVED" ;
    hw3:hasResidual "0.00053"^^xsd:double ;
    hw3:hasSolutionTrajectory stu:ik_target_near_traj ;
    hw3:hasJointConfiguration stu:ik_target_near_q .

# solver 收斂軌跡:9 次迭代,降採樣為 6 個樣本
stu:ik_target_near_traj a hw3:SolverTrajectory ;
    hw3:hasSampleCount 6 ;
    hw3:hasTotalIterationCount 9 ;
    hw3:hasTrajectorySample stu:ik_target_near_traj_s0 , ... , _s5 .

stu:ik_target_near_traj_s0 a hw3:TrajectorySample ;
    hw3:hasSampleIndex 0 ;
    hw3:atSolverIteration 0 ;
    hw3:hasSampleResidual "0.084313"^^xsd:double ;
    hw3:hasJointConfiguration stu:ik_target_near_traj_s0_q ;  # 關節空間
    hw3:hasEndEffectorPose stu:ik_target_near_traj_s0_ee ;    # 工作空間 (FK)
    dul:directlyPrecedes stu:ik_target_near_traj_s1 .

semantic/output/task2_ik_graph.ttl

為下游而 ground：結構化 soma:JointState → 練習 1（與限位 join）；solver 軌跡 → 練習 2（收斂分析）；共用 target URI + 狀態 → 練習 3 / q2 / q3（跨機器人互查）。

推理導出 · Task 2 評估類

hw3:SolvedIKComputation ≡ hw3:IKComputation ⊓ (hw3:hasIKStatus value "SOLVED")

互通性展示：TA 的 UR10 圖（ta:）對同樣的 target 發佈結果 — target_mid 對 UR10 是 SOLVED、對 UR5 是 OUT_OF_REACH，臂長差異直接呈現在語意層。

TASK 3

Transporter Network — 積木插入

用自己的 IK 驅動 Transporter Network 完成 block insertion（prepick → grasp → preplace → insertion）。語意層 ground 每個測試 episode 的結果。

過程

  1. 下載 block-insertion-easy-test/ 資料集與 checkpoints/ 至 ravens/。
  2. ravens/test.py 以 your_ik 執行 10 個 episode，寫出 block-insertion-easy-transporter-*.pkl（每回合 total reward）。
  3. semantic/ground_task3_insertion.py 讀 pkl，reward ≥ 0.999 → SUCCESS，否則 FAILURE → output/task3_insertion_graph.ttl。

語意定義

詞彙來源定義
soma:EpisodeSOMA一次測試回合（比照 KnowRob NEEM 的 episode 建模）
hw3:performsTaskhw3:任務名（"block-insertion-easy"）
hw3:episodeIndex / hasReward / hasOutcomehw3:回合序、總獎勵（xsd:double）、"SUCCESS"/"FAILURE"
hw3:manipulatesObjecthw3:episode → 被操作物件（stu:ell_block）
hw3:GraspableObject、hw3:isKinematicallyReachablehw3:場景語意：可抓取性（感知層）、可達性（由執行成功 ground）——餵給 Task 4 的 semantic gate

範例（你的圖應長這樣）

為下游而 ground：episode → q4 報表；場景語意三元組（graspable / reachable）是練習 4 semantic gate 的原料——完成 gate 規則後，同樣的推理也適用於這個真實場景。

TASK 4

Semantic Knowledge & Triple Store

把 Task 1–3 的知識圖與 TA 的 UR10 圖經 OWL 推理後載入 TDB2 triple store，用 SPARQL 讀出所有任務的評估，並以四個引導式練習走到語意決策——這一層不產生新數值，只做推理、互查與決策。

學習目標

  1. Symbol Grounding：把數值層事實轉成引用標準本體的結構化 RDF（不是 JSON 字串），並理解「為下游而 ground」——每個欄位都有明確的消費者。
  2. OWL Reasoning：用 equivalentClass（intersectionOf + hasValue）讓評估類由推理導出，而非程式寫死；理解 OWL 做不到數值比較，門檻判斷屬於數值層。
  3. Triple Store 與互通性：共用詞彙 + 共用 target URI + provenance，使獨立開發的程式（你的 UR5、TA 的 UR10、其他組）可載入同一 store 直接互查。
  4. Semantic Decision Making：從資料查詢一路走到 ALLOW/REFUSE 決策——語意閘門（練習 4）用推理結果直接裁決機器人動作，且每個裁決可解釋。

② IK 結果 groundingground_task2_ik.py → ik_result_to_triples()結構化 JointConfiguration 用 common.joint_config_to_ttl；軌跡用 trajectory_out=[] + common.trajectory_to_ttl

決策推理 · Semantic Gate（練習 4・加分項目）

gate 的兩個條件各來自一層：graspability（感知層，Task 3 場景語意）、reachability（IK／執行結果）。詞彙與類宣告已在本體 §3b 提供，但推理規則是學生的工作——在練習 4（加分項目）自己定義 equivalentClass，讓 reasoner 導出可執行目標：

推理導出 · 三條件 gate（學生定義）

hw3:ExecutableGraspTarget ≡ hw3:GraspableObject ⊓ (hw3:isKinematicallyReachable value true)

場景圖只含 graspable / reachable 事實，成員絕不手動 assert——全由 reasoner 從這條規則導出（概念分類交給 OWL，數值判斷留在數值層）。

Gate 測試案例（預期結果）判決與可解釋理由
Object A · 桌上積木（graspable ✓ reachable ✓）ALLOW——由你的規則導出
Object B · 固定 fixture（graspable ✗ reachable ✓）REFUSE——reachable BUT NOT GraspableObject（語意排除）
Object C · 工作空間外積木（graspable ✓ reachable ✗）REFUSE——幾何排除

延伸視野：同一套 gate 也能接進真實的 Ravens 執行流程——每個 pick-and-place 動作執行前先經 OWL 推理裁決（ALLOW 才執行），並把每筆決策連同結構化 pick pose 記錄成知識圖，事後可用 SPARQL 回查每個動作為何被允許或拒絕。

最終推論能做什麼 · 學生可以做哪些

Jena OWL reasoner 在這套本體上會導出五類推論；結構化表示讓 SPARQL 能「伸進」組態、pose 與軌跡內部——以下是作業可指派的練習選單與設計界線。

推理引擎實際導出的五類推論

推論類型機制例子
等價類成員intersectionOf + hasValuePassedFKComputation / SolvedIKComputation / SuccessfulEpisode / ExecutableGraspTarget — 程式從不寫入這些 type，全由推理具體化
類階層rdfs:subClassOf 遞移查「所有 dul:Event」自動涵蓋 FK＋IK 計算；RevoluteJoint 個體同時是 soma:Joint
屬性階層rdfs:subPropertyOf?x dul:hasComponent ?y 一條查詢同時取回 機器人→關節、組態→關節狀態、軌跡→樣本 三層部分關係
型別推導domain / range掛了 hasJointState 的節點自動被分類為 JointConfiguration
一致性檢查validate()裸浮點（xsd:decimal）、langString 等 range 違規會被報告——型別化 literal 紀律的教學點
