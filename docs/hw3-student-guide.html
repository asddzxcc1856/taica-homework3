共通語意基座

整個作業採三層式架構：數值層產生事實，Grounding 層把事實轉成 RDF，SHACL 驗證層從語意資料中發現執行問題。

1 · 數值層fk.py / ik.py / fsm_task.py — 關節角、pose、殘差、回合結果（PyBullet 模擬）
│ Symbol Grounding（ground_task*.py + common.py 序列化 helper）▼
2 · 語意層hw3-ontology.ttl 共用詞彙 ＋ 你的執行過程知識圖 data.ttl（結構化節點）
│ Jena shacl CLI ▼
3 · 驗證層SHACL（你的 shapes.ttl ＋ TA 完整版）：從數值發現 ARM_OUT_OF_RANGE / NO_CONVERGENCE / FK_INACCURATE，含 TA 提供的有問題執行過程

命名空間

PrefixIRI角色
cora:purl.org/ieee1872-owl/cora-bare#IEEE 1872 CORA — 機器人（cora:Robot）
soma:ease-crc.org/ont/SOMA.owl#SOMA — 關節、關節狀態、6D pose、episode、軌跡
pos:purl.org/ieee1872-owl/pos#IEEE 1872 POS — Position / Orientation / Pose
dul:ontologydesignpatterns.org/ont/dul/DUL.owl#DUL 上層本體 — Event / Region / hasComponent 上位對齊
qudt: unit:qudt.org/schema/qudt/ · qudt.org/vocab/unit/QUDT 單位 — unit:M（公尺）、unit:RAD（弧度）

結構化三原則

  1. 不用 JSON 字串。Pose 與關節向量是結構化節點：soma:6DPose = pos:Position（x/y/z）＋ hw3:QuaternionOrientation（qx/qy/qz/qw）＋ 參考座標系；關節組態 = hw3:JointConfiguration 聚合 6 個 soma:JointState，每個以 hw3:isStateOfJoint 指回關節個體。
  2. 數值是型別化 literal、單位是 QUDT IRI。一律 "..."^^xsd:double（裸浮點會變 xsd:decimal 觸發 range 檢查錯誤）；qudt:hasUnit unit:M / unit:RAD。
  3. 每個個體帶 hw3:producedBy。provenance 讓不同來源的圖合併後仍可區分——這是語意資料可交換的基本紀律。
標準引用 既有本體詞彙（IRI 與官方一致，離線存根） hw3: 自創 課程特有概念 SHACL 偵測 由 shapes 從數值中發現的問題旗標（ARM_OUT_OF_RANGE 等）
TASK 1

Forward Kinematics — 正向運動學

實作 your_fk()：classic DH 連乘求 EE pose ＋ 幾何 Jacobian。語意層 ground 兩件事：機器人規格（關節個體＋DH 參數）與每筆測資的評估結果。

過程

  1. 實作 fk.py 的 your_fk(DH_params, q, base_pos)；python fk.py 以 easy / medium / hard 測資評分（pose 誤差門檻 0.005、Jacobian 門檻 0.05，各 10%）。
  2. semantic/ground_task1_fk.py 對 3 筆 easy 測資執行 your_fk，與 ground truth 比對得 pose_error / jacobian_error → PASS / FAIL。
  3. Ground 機器人規格：stu:my_ur5 a cora:Robot ＋ 6 個 soma:RevoluteJoint 個體（DH a/d/α、限位、關節序）。
  4. Ground 每筆 FK 評估：輸入關節組態與 EE pose 都是結構化節點 → 輸出 output/task1_fk_graph.ttl。

語意定義

詞彙來源定義
cora:RobotCORA機器人個體（stu:my_ur5、ta:ta_ur10）
soma:RevoluteJointSOMA旋轉關節個體，掛 hw3:jointIndex、hw3:dh_a / dh_d / dh_alpha、上下限位
hw3:hasJointhw3:機器人 → 關節（⊑ dul:hasComponent）
hw3:FKComputationhw3:一次 FK 計算（⊑ hw3:KinematicComputation ⊑ dul:Event）
hw3:hasInputJointConfigurationhw3:ObjectProperty → hw3:JointConfiguration（6 × soma:JointState）
hw3:hasEndEffectorPosehw3:ObjectProperty → soma:6DPose（world frame）
hw3:hasPoseError / hasJacobianErrorhw3:與 GT 的 L2 誤差（xsd:double）——SHACL 的 FK_INACCURATE shape 讀 pose error

規格欄位的用途：DH 與限位由 TA 的 STRUCTURE shapes 驗證完整性（S1 評分）；限位另被 SHACL-SPARQL 的 JOINT_LIMIT_VIOLATION 交叉檢查讀取。

範例（你的圖應長這樣）

# 機器人規格:關節是 soma:Joint 個體,帶 classic DH 參數
stu:my_ur5_joint1 a soma:RevoluteJoint ;
    hw3:jointIndex 1 ;
    hw3:dh_a "0.0"^^xsd:double ;  hw3:dh_d "0.0892"^^xsd:double ;
    hw3:dh_alpha "1.570796"^^xsd:double ;
    hw3:hasJointLowerLimit "-4.712389"^^xsd:double ;
    hw3:hasJointUpperLimit "-1.570796"^^xsd:double .

# 一筆 FK 評估:輸入組態與 EE pose 都是結構化節點
stu:fk_case_0 a hw3:FKComputation ;
    hw3:producedBy "313551000" ;
    hw3:computedForRobot stu:my_ur5 ;
    hw3:hasInputJointConfiguration stu:fk_case_0_q ;
    hw3:hasEndEffectorPose stu:fk_case_0_ee ;
    hw3:hasPoseError "0.000625"^^xsd:double ;
    hw3:hasJacobianError "0.000316"^^xsd:double .

stu:fk_case_0_q_js1 a soma:JointState ;          # 之一,共 6 個
    hw3:isStateOfJoint stu:my_ur5_joint1 ;       # 指回關節個體
    qudt:hasUnit unit:RAD ;
    soma:hasJointPosition "-3.154407"^^xsd:double .

stu:fk_case_0_ee a soma:6DPose ;
    hw3:hasReferenceFrame "world" ;
    hw3:hasPositionComponent stu:fk_case_0_ee_pos ;
    hw3:hasOrientationComponent stu:fk_case_0_ee_ori .
stu:fk_case_0_ee_pos a pos:Position ;
    qudt:hasUnit unit:M ;
    hw3:hasPositionX "0.287046"^^xsd:double ;
    hw3:hasPositionY "0.233046"^^xsd:double ;
    hw3:hasPositionZ "0.912072"^^xsd:double .

SHACL · Task 1 的驗證角色

FK 準確度由 shapes.ttl 的 worked example 驗證：hasPoseError ≤ 0.005，違反 → FK_INACCURATE。TA 的有問題執行過程裡有一筆 pose 誤差 0.031 的 FK，你的 shapes 必須抓到它。

TASK 2

Inverse Kinematics — 逆向運動學

實作 your_ik()：Damped Least Squares 迭代解，靠 your_fk 提供 pose 與 Jacobian。語意層 ground 兩件事：求解狀態與結構化關節解。

過程

  1. 實作 ik.py 的 your_ik(robot_id, pose, base_pos, ...)；python ik.py 評分（誤差門檻 0.02，40%）。
  2. semantic/ground_task2_ik.py 對三個共用目標（hw3:target_near / target_mid / target_far）呼叫 your_ik。
  3. 依殘差與工作空間幾何判定狀態：SOLVED / OUT_OF_REACH / NO_CONVERGENCE。
  4. 結構化 grounding（關節解 = 6 個 soma:JointState）→ output/task2_ik_graph.ttl。

語意定義

詞彙來源定義
soma:6DPose（⊑ pos:Pose, dul:Region）SOMA共用目標 hw3:target_*：跨圖比較的 join key，座標在 pos:Position 元件節點上
hw3:IKComputationhw3:一次 IK 計算（⊑ dul:Event）
hw3:solvesForTargethw3:IK → 目標 pose（⊑ dul:hasRegion）
hw3:hasIKStatus / hasResidualhw3:求解狀態字串（數值層判定）、Cartesian 殘差（SHACL NO_CONVERGENCE 的輸入）
hw3:hasTargetDistancehw3:目標與肩部的距離（公尺，數值層計算）——SHACL ARM_OUT_OF_RANGE 的輸入
hw3:hasJointConfigurationhw3:ObjectProperty → 結構化 hw3:JointConfiguration（每個關節一個 soma:JointState，指回關節個體）

範例（你的圖應長這樣）

stu:ik_target_near a hw3:IKComputation ;
    hw3:producedBy "313551000" ;
    hw3:computedForRobot stu:my_ur5 ;
    hw3:solvesForTarget hw3:target_near ;        # 共用 URI = join key
    hw3:hasIKStatus "SOLVED" ;
    hw3:hasResidual "0.00053"^^xsd:double ;
    hw3:hasTargetDistance "0.62691"^^xsd:double ;
    hw3:hasJointConfiguration stu:ik_target_near_q .

stu:ik_target_near_q_js1 a soma:JointState ;   # 之一,共 6 個
    hw3:isStateOfJoint stu:my_ur5_joint1 ;      # 指回關節個體
    qudt:hasUnit unit:RAD ;
    soma:hasJointPosition "-3.068552"^^xsd:double .

semantic/output/task2_ik_graph.ttl

Grounding 的用途：結構化 JointState 受 TA STRUCTURE shapes 驗證（每組態恰 6 個、皆為 xsd:double）；距離、殘差與誤差餵 SHACL——同一份執行資料直接支撐宣告式驗證。

SHACL · Task 2 的驗證角色

hasTargetDistance ≤ 0.90 違反 → ARM_OUT_OF_RANGE；hasResidual ≤ 0.02 違反 → NO_CONVERGENCE——兩個 shape 都是你在 shapes.ttl 要實作的 TODO，直接從 grounding 的數值發現執行問題。

TASK 3

FSM Manipulation Pipeline — 有限狀態機操作管線

不再使用學習模型與 ravens——一個確定性的 Finite State Machine（fsm_task.py，TA 提供、無學生 TODO）驅動 UR5 完成 10 個 seeded pick-and-place 回合，逐狀態驗證你的 IK 與 FK。

狀態機

MOVE_TO_PREPICK → DESCEND_TO_PICK → GRASP → LIFT
    → MOVE_TO_PREPLACE → DESCEND_TO_PLACE → RELEASE → RETREAT
    → VERIFY → SUCCESS / FAILURE

每個運動狀態的雙重驗證

驗證機制失敗訊息
IK 驗證目標 pose 由 your_ik 求解 → position control 執行 → 實際 EE 位置須在指令 3 cm 內IK_MISS in <STATE>
FK 驗證your_fk 代入量測到的關節角，與模擬器 EE 位置比對須在 1 cm 內——運動學模型逐狀態對照物理FK_MISMATCH in <STATE>
抓取／放置DESCEND_TO_PICK 逐步下降至吸盤回報接觸；GRASP/RELEASE 切換吸附約束；VERIFY 要求積木落在目標 6 cm 內NO_CONTACT／GRASP_FAILED／PLACE_MISS

過程

  1. python fsm_task.py（加 -g 開 GUI 觀看）——不需下載任何資料集或 checkpoint。
  2. 10 個 seeded 回合：積木與目標位置由亂數種子決定、皆落在 Task 1/2 測資已覆蓋的工作區內；大幅移動採 warm-start 重解（同 Task 2 連續軌跡的收斂方式）。
  3. 預期輸出：Episode k/10 | SUCCESS × 10 → Total Score : 10.000 / 10.000；失敗會指名是哪個狀態、什麼原因——FSM 把「運動學壞在管線何處」定位出來。

Task 3 不做 grounding——語意層（Task 4）聚焦在 FK/IK 的執行過程資料。

TASK 4

Semantic Grounding（REUSE）＋ SHACL 驗證

把 FK/IK 的執行過程數值帶進語意空間，再讓語意層自己找出哪裡出了問題。學生實作兩件事：grounding 與 SHACL。

學生實作項目

實作檔案（含 worked example）產物
① Grounding——ontology API 函式，REUSE 標準本體把執行資料轉成語意資料ground_execution.py：fk_computation_to_triples 為範例；TODO = robot_spec_to_triples、ik_computation_to_triplesoutput/data.ttl
② SHACL——驗證 shapes，從數值發現執行過程的問題狀態shapes.ttl：FK 準確度 shape 為範例；TODO = ARM_OUT_OF_RANGE（distance ≤ 0.90）、NO_CONVERGENCE（residual ≤ 0.02）output/validation.ttl

過程（run_task4.sh，五步）

  1. 工具鏈檢查 ＋ 準備 Apache Jena（shacl CLI 做驗證）。
  2. Grounding：跑 your_fk（3 筆測資 vs GT）與 your_ik（near / mid / far 三個固定目標）→ data.ttl（含 hasTargetDistance、結構化 JointConfiguration）。
  3. SHACL × 3：你的 shapes 驗自己的 data → validation.ttl；TA 完整 shapes（ta-shapes-full.ttl）驗你的 data；你的 shapes 驗助教提供的 24 筆執行紀錄資料集（ta-faulty-execution.ttl），結果逐筆與標準答案 ta-answer-key.json 比對。
  4. 評分：score_semantic.py 解析三份驗證報告 → 30 分。

組成筆數標準答案（ta-answer-key.json）

設計原則（評分也依此設計）

SHACL 直接驗證數值：門檻檢查（reach 0.90 m／residual 0.02 m／pose error 0.005 m）以宣告式 constraints 表達，取代手寫驗證程式。TA 完整版 ta-shapes-full.ttl 另含 STRUCTURE 結構檢查（REUSE 正確性）與 SHACL-SPARQL 關節限位交叉檢查，作為自動評分依據。

評分（Task 4 · 30 分）

S1 grounding 結構（TA STRUCTURE shapes 零違規，12）· S2 自己資料的問題偵測（mid/far 標旗、near 乾淨、零限位違規，8）· S3 你的 shapes 驗 TA 24 筆資料集、逐筆對答案（偵測 8 分 ＋ 不誤報 2 分，按答對比例給分）。
