HW3: Robot Manipulation & Semantic Robot Knowledge

Build the kinematic core of a UR5 robot arm, use it in a pick-and-place state machine, then represent and validate the execution as a semantic knowledge graph.

What you will build

This homework connects numerical robot kinematics with a complete manipulation pipeline and structured semantic data. Complete the tasks in order: later tasks directly use the functions you implement earlier.

1. KinematicsImplement forward kinematics (FK) and iterative inverse kinematics (IK) for the six-joint UR5.
2. ManipulationUse your FK and IK inside a deterministic finite-state machine for pick-and-place episodes.
3. SemanticsGround robot specifications and FK/IK executions in RDF, then validate them with SHACL.

TASK 1 · 20 POINTS

Forward Kinematics

Implement the UR5 forward-kinematics function using the classic D-H convention. Your result must provide both the end-effector pose and the geometric Jacobian.

Implement

  1. Open fk.py and review get_ur5_DH_params().
  2. Implement your_fk(DH_params, q, base_pos).
  3. Return (pose_7d, jacobian): the pose is [x, y, z, qx, qy, qz, qw] and the Jacobian is a 6×6 geometric Jacobian.
  4. Do not call PyBullet APIs for the calculation, and do not modify the supplied adjustment block at the end of the function.

Verify

python fk.py            # easy, medium, and hard test cases
python fk.py -g         # optional PyBullet GUI
python fk.py -g -vp     # GUI with end-effector pose visualization

Both the pose and Jacobian reports should have an error count of zero for every visible test file. Hidden test cases are also used for grading.

Jacobian reminder. For a revolute joint, use the preceding frame axis: the linear component is z(i-1) × (p_end − p(i-1)), and the angular component is z(i-1).
TASK 2 · 40 POINTS

Inverse Kinematics

Implement an iterative, Jacobian-based IK solver. The solver will be used with its default arguments during grading, so tune those defaults carefully.

Implement

  1. Open ik.py and implement your_ik(robot_id, new_pose, base_pos, ...).
  2. Use your own your_fk() and Jacobian in each iteration. Damped least squares or a pseudo-inverse method are appropriate.
  3. Compute both translational and rotational pose error, apply a stable update, and respect the supplied joint limits.
  4. You may inspect pybullet_ik() as a reference, but your solution must not call PyBullet IK APIs.

Verify

python ik.py

The three visible test sets should report zero errors, with mean positional error in the 10−3 range. If results fluctuate, review damping, step rate, stopping threshold, iteration count, and warm-start behavior.

TASK 3 · 10 POINTS

FSM Manipulation Pipeline

Your kinematics now control ten seeded UR5 pick-and-place episodes. This is an integration task: fsm_task.py is provided and should not be changed.

State flow

MOVE_TO_PREPICK → DESCEND_TO_PICK → GRASP → LIFT
  → MOVE_TO_PREPLACE → DESCEND_TO_PLACE → RELEASE → RETREAT
  → VERIFY → SUCCESS / FAILURE
Validation Requirement Failure message
IK After position control, the achieved end-effector position is within 3 cm of the commanded target. IK_MISS in <STATE>
FK Your FK, evaluated on measured joint angles, agrees with the simulator end-effector position within 1 cm. FK_MISMATCH in <STATE>
Task events The gripper must contact, grasp, release, and place the block within 6 cm of the goal. NO_CONTACT, GRASP_FAILED, or PLACE_MISS

Run

python fsm_task.py
python fsm_task.py -g    # optional GUI

A complete result reports ten successful episodes and a total score of 10.000 / 10.000. Failure names help identify which state exposes the kinematics issue.

TASK 4 · 30 POINTS

Semantic Grounding (REUSE) & SHACL Validation

Convert the numerical FK/IK execution process into structured RDF, then use SHACL to discover invalid or problematic executions directly from those values.

Part A: ground execution data

Read semantic/ontology/hw3-ontology.ttl and reuse standard vocabulary wherever possible.

Concept Required representation
Robot cora:Robot from IEEE 1872 CORA
Joints and states soma:RevoluteJoint and soma:JointState
Pose soma:6DPose, composed of a pos:Position and quaternion orientation
Units QUDT IRIs, including unit:M and unit:RAD
Numbers Typed xsd:double literals on structured RDF nodes — never JSON strings
  1. Read the worked example fk_computation_to_triples() in semantic/ground_execution.py.
  2. Implement robot_spec_to_triples() for all six joints, including D-H parameters and joint limits.
  3. Implement ik_computation_to_triples() for status, residual, target distance, and a structured joint configuration.
  4. Use the supplied serializers in semantic/common.py, especially pose_to_ttl and joint_config_to_ttl.

Part B: write SHACL shapes

The worked FK shape flags FK_INACCURATE when pose error is greater than 0.005. Add two shapes for hw3:IKComputation:

  • hw3:hasTargetDistance must be at most 0.90; its message must start with ARM_OUT_OF_RANGE:.
  • hw3:hasResidual must be at most 0.02; its message must start with NO_CONVERGENCE:.
Thresholds are inclusive. Use sh:maxInclusive, not sh:maxExclusive. Records exactly at 0.90 m, 0.02 m, or 0.005 m are conforming.

Run and interpret the results

bash semantic/run_task4.sh --group <your-group-id>

The script checks the grounding structure, validates your generated data.ttl, validates the 24-record TA dataset, and scores the results. With a correct implementation, target_mid and target_far are flagged as out of range, while target_near stays clean.

If the structural check fails, inspect semantic/output/ta-validation.ttl. If the TA-data check differs from the answer key, the scorer prints each expected [...] , got [...] mismatch. Check the exact message prefixes and thresholds first.
